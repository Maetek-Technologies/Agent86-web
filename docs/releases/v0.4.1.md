# agent86-web v0.4.1

What agent86 1.0.21 adds over ACP, in the browser: who is asking for an approval, what is waiting behind it, and threads that survive agent86 stopping partway through a turn.

```sh
npm install -g agent86@latest       # 1.0.21 for everything below; 1.0.15 or newer still works
npm install -g agent86-web@latest
```

Every feature is detected from what agent86 advertises or sends, never from its version. With agent86 1.0.20 or older, the thread looks and reconnects as it did in 0.4.0.

## New

- **Who is asking.** When a sub-agent (a delegated specialist) needs your approval, the approval panel says which one asks, with a link to its delegation card, whether it works in an isolated git worktree (and on which branch), and what it has spent so far beside the turn's spend and the cost cap. The main agent's own approvals look as before.
- **An approval inbox.** When specialists run in parallel, agent86 1.0.21 asks their questions one at a time, in the order they arrived. A list beside the thread shows the question being asked and those waiting behind it (which sub-agent, which tool, a link to its card, the project specialist for a one-time specialist approval), with a count. You still answer the open request on its card; the list shows what is coming. Stopping the turn empties it.
- **Reconnecting without a replay.** When a thread's connection to agent86 comes back (agent86 was restarted, the project was trusted, the connection dropped while idle), agent86-web reopens the session with `session/resume` and carries on from the conversation already on screen, instead of having agent86 send it all again. A reloaded page, which has no copy, still uses `session/load`.
- **Surviving agent86 stopping mid-turn.** agent86 1.0.21 saves a session after every step. If agent86 dies or is killed partway through a turn, the thread reconnects to a new agent86 with the steps it finished, marks the turn **Interrupted**, and offers **Continue**, which sends "Continue where you left off." agent86 cannot yet carry on the cut-off turn by itself (planned for agent86 1.0.24); the model sees everything done before.

## Changed

- A cost under $0.0001 shows as "<$0.0001" rather than "$0.0000".
- agent86-web's log (the terminal it runs in) names each agent86 process's id when it starts.

## Upgrading

Nothing to change.

## Security and privacy

- The bridge lets `session/resume` through with the same checks as `session/load`: the working directory must be the thread's workspace, and any MCP servers the page names are removed (T7, T8 in [docs/SECURITY.md](https://github.com/Maetek-Technologies/Agent86-web/blob/main/docs/SECURITY.md)).
- Who asks and the inbox come from agent86's state events, which agent86 redacts as it does its trace (a secret shows as `${secret:NAME}`). They stay in memory with the session and are never logged or stored.
