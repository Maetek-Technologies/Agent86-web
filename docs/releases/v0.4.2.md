# agent86-web v0.4.2

What agent86 1.0.22 and 1.0.23 add over ACP, in the browser: see and correct what agent86 remembers, and hand it secrets without leaving the page. Plus: restarting agent86-web no longer replays your open threads.

```sh
npm install -g agent86@latest       # 1.0.23 for everything below; 1.0.15 or newer still works
npm install -g agent86-web@latest
```

Every feature is detected from what agent86 advertises, never from its version. With agent86 1.0.21 or older, the thread looks as it did in 0.4.1.

## New

- **Memory.** With agent86 1.0.22, a **memory** button in the thread header opens what agent86 has learned: facts (what the agent keeps with `remember`) and episodes (one per finished turn, recalled into similar later tasks), newest first, 20 at a time. Pin an entry so pruning never removes it, show only pinned ones, or forget one (after a confirmation). It is the same memory as `agent86 memory list` at the terminal. agent86 does not answer while a turn runs, so the panel waits for the turn to end.
- **Secrets.** With agent86 1.0.23, a **secrets** button lists the secrets the session holds (names only, with a badge for those remembered for the project), lets you add one through a masked entry, optionally remembering it in the OS keyring for this project as the terminal's `/secret NAME` does, and forget one. The model only ever sees the name: it uses the secret as `$NAME` in commands and `${secret:NAME}` in files.
- **When the model asks for a secret.** agent86 1.0.23 can ask for a secret it needs (`request_secret`). agent86-web shows a masked prompt over the conversation with the model's reason, a note when it would replace a value already held, and the remember choice (already on when the secret is remembered). Enter sends it; Decline, Esc, closing the prompt, Stop, and the turn ending all decline it, and the model is told. It is listed in the approval inbox as "a secret: NAME".
- **Restarting agent86-web keeps your threads on screen.** Opening agent86-web's new link in a tab that is still open signs it in again without reloading, so each thread reconnects with the conversation it shows and, with agent86 1.0.21 or newer, resumes without agent86 sending it all again.

## Changed

- `/secret <something>` typed in the message box is no longer sent when agent86 takes secrets from agent86-web: what you type there would stay in the thread and its history. The secrets panel opens instead. `/secret` alone and `/secret forget NAME` still go to agent86.

## Upgrading

Nothing to change. A secret you add without remembering it is held by that agent86 process only: when agent86 restarts (agent86-web stops an idle one after `--idle-timeout`), it is gone. Remember it for the project to keep it.

## Security and privacy

- What you type for a secret goes from a masked entry straight to agent86 over the local connection. It is never kept in the page's state, the thread, its prompt history, browser storage, the address bar, or a log, and the entry is cleared once it is sent. agent86 shows the value as `${secret:NAME}` everywhere afterwards, and never repeats it in a reply or an error.
- agent86-web tells agent86 that it draws a masked entry (`clientCapabilities._meta["com.maetek.agent86/secrets"]`), which is what lets the model ask. The bridge passes that claim, and the six new memory and secret requests, and still drops everything else (T9, T22, T23 in [docs/SECURITY.md](https://github.com/Maetek-Technologies/Agent86-web/blob/main/docs/SECURITY.md)). A secret request that no open tab can answer is declined.
- The bridge never logs message bodies. For debugging, `AGENT86_WEB_TRANSCRIPT=<file>` records every relayed message, with a secret's value written as `<hidden>`, as agent86's own transcript does. It holds your prompts and file contents, so keep it private and delete it when done.
